Hardware

Two boards, one sensor, and the one part that keeps 5 V out of a 3.3 V pin.

Parts

  • 2× Seeed XIAO ESP32-C3 with the u.FL antennas that ship with them.
  • HC-SR04 ultrasonic distance sensor (the common 4-pin 5 V module).
  • A bidirectional logic level shifter (any 4- or 8-channel 3.3 V ⇄ 5 V breakout). Only one channel is used, for ECHO.
  • Breadboard and jumper wires for the sensor board; a USB bank to power it.
  • USB-C data cables (not charge-only).

Swappable sensor: the firmware’s read_sensor() can return a photoresistor, pot, or TMP36 reading instead — the payload and page don’t change.

Things that bite

  • ECHO must go through the level shifter. Skipping it feeds 5 V into a 3.3 V pin.
  • HC-SR04 is flaky on soft or angled surfaces; a flat hand or a book reads best.
  • If the antenna is loose you’ll see LINK LOST. Check the u.FL first.
  • Both boards pin channel 6; keep them matched.
  • If you add wiring of your own, keep anything tied to ground at power-up off D0, D8 (SCK) and D9 (MISO): on the ESP32-C3 they are boot-strapping pins.
  • A board that won’t take firmware: hold BOOT (B), tap RESET (R), release BOOT, then try again.

Pinout detail is in wiring/wiring.md.

Put the firmware on the boards

Two roles, bridge and sensor, each a single code.py written straight from this page. Chrome or Edge.

1. Plug in

Connect one XIAO ESP32-C3 over USB. If the instrument is connected to a board, this page disconnects it first.

2. Pick its job

Install bridge for the board that stays at the laptop and receives. Install sensor for the board with the HC-SR04. Pick the port named USB JTAG/serial debug unit.

3. Wait for the boot line

The page writes code.py over CircuitPython’s REPL, checks its size and CRC on the board, reboots it, and waits for the firmware’s first line. Then do the other board.

4. Connect

Back on the instrument, click Connect bridge and pick the bridge’s port. Or skip all of this: Try without hardware runs the page against a simulator.

The sensor board also needs one library. The sensor firmware imports adafruit_hcsr04, which this page can’t install. Once, per sensor board: download the CircuitPython library bundle for your CircuitPython version, and put adafruit_hcsr04.mpy into the board’s lib/ folder with Thonny (File → Open → CircuitPython device shows the filesystem; drag the file into lib/) or the CircuitPython web editor. The bridge needs nothing extra.
Ready. Plug a board in and pick its role.
No CircuitPython on that board. A XIAO ESP32-C3 fresh from the bag runs Seeed’s factory sketch, not CircuitPython. Install CircuitPython once with the button below, then come back to Install bridge or Install sensor.

Doing it by hand instead
  • Thonny: Tools → Options → Interpreter → CircuitPython (generic), pick the port, open firmware/bridge/code.py or firmware/sensor/code.py, then File → Save as… → CircuitPython device, name it code.py. For the sensor board, also copy adafruit_hcsr04.mpy into lib/.
  • CircuitPython from a terminal: pip install esptool, then esptool.py --chip esp32c3 --port COMn erase_flash and esptool.py --chip esp32c3 --port COMn write_flash 0x0 adafruit-circuitpython-seeed_xiao_esp32c3-en_US-<version>.bin.
  • The REPL exchange the page uses is written out in PROTOCOL.md.

Swapping sensors? Edit read_sensor() in the sensor code.py to return (raw, value_mm) — the payload and page stay the same.

About this demo

What it shows, how to run it in front of a room, and how the bytes become a number.

What it shows

A sensor on one board, a screen across the room. The sensor measures distance with sound (like a bat or a parking sensor), packs the reading into a few bytes, and radios it to a second board plugged into the laptop. You see the number and, right next to it, the exact bytes that carried it — so “data” and “the thing that moved through the air” are the same object on screen.

Try this during the tour: wave a hand in front of the sensor and watch the line and the bar follow it. Cover the sensor completely and the line holds and flags “no echo” instead of lying with a zero.

How it works

The sensor board reads the HC-SR04, puts both the raw echo time (µs) and the computed distance (mm) into a 16-byte packet, and broadcasts it over ESP-NOW → the bridge checks the CRC and prints one JSON line per packet → this page plots the distance and shows the raw bytes with the distance field highlighted. A distance of 0xFFFF means “no echo,” which the page shows as a held line, not a zero. The line format and payload layout are in PROTOCOL.md.

Known quirks:

  • The raw µs and the mm are the same measurement — the sensor gives one, the firmware computes the other from it (×58 µs/cm). That’s the point of showing both.
  • HC-SR04 is flaky on soft or angled surfaces; a flat hand or a book reads best.
  • If the antenna is loose you’ll see LINK LOST. Check the u.FL first.
